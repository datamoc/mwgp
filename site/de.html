Ihre RPG-Maker-Spiele — in jedem Browser spielbar und bearbeitbar.

MWGP wandelt Spiele aus RPG Maker MV, MZ, XP, VX und VX Ace in ein portables Manifest (mwgp.json) mit dekodierten Ressourcen um. Umgewandelte Spiele laufen offline im Browser, und mit dem MWGP Studio lassen sie sich ansehen und bearbeiten — Karten, Ereignisse, Dialoge, Datenbank und Ressourcen — ohne RPG Maker zu öffnen. Die Umwandlung läuft entweder mit Node.js (der Referenzversion) oder direkt in Ihrem Browser aus einer einzigen eigenständigen Datei: keine Installation, kein Server, und Ihre Spieldateien verlassen Ihren Computer nie.

Node-Version oder Browser-Version?

Node-Version (Referenz)Browser-Versionen (eigenständig)
Konverter Die Befehle convert-mv, convert-rgss und convert:auto wandeln ganze Bibliotheken um, schreiben in echte Ordner, schützen bearbeitete Projekte bei erneuter Umwandlung und sind durch die Testsuites des Projekts abgedeckt. Eine einzige HTML-Datei wandelt ein Spiel nach dem anderen um, vollständig auf Ihrem Computer, und erzeugt eine spielbare Seite, eine ZIP-Datei oder einen Ordner. Gleiche Umwandlungsregeln und Kompatibilitätsgrenzen wie die Befehlszeile.
Studio Das Server-Studio bearbeitet umgewandelte Ordner auf der Festplatte: geschützte Speicherstände, Ressourcen-Versionen, Vergleich mit der letzten Umwandlung und Prüfung durch den vollständigen MWGP-Validator vor jeder Veröffentlichung. Das eigenständige Studio bearbeitet eine eigenständige Spielseite im Speicher und lädt eine neu erzeugte Seite herunter. Derselbe grafische Editor, ohne Server.
Player Der Launcher stellt Ihre Bibliothek lokal bereit und spielt umgewandelte Spiele im Browser. Jede spielbare Seite enthält Player, Runtime und Ressourcen; Spielstände liegen im Speicher des Browsers.

Grenzen der eigenständigen Versionen

  • Alles läuft im Speicher des Browsers: Sehr große Spiele können mehr brauchen, als ein Browser-Tab halten kann; bevorzugen Sie dann den Node-Konverter oder die Ordner-Ausgabe.
  • Direktes Schreiben in Ordner braucht die File System Access API (Chromium); sonst nutzen Sie den ZIP-Download. Der ZIP-Export folgt den klassischen ZIP-Grenzen (unter 4 GiB, weniger als 65.535 Dateien).
  • Spielseiten brauchen einen aktuellen Browser mit gzip-Dekompression (DecompressionStream). Spielstände werden pro Spiel im Browser gespeichert, nicht in die HTML-Datei zurückgeschrieben.
  • Das eigenständige Studio hält Änderungen im Speicher, bis Sie die neu erzeugte Spielseite herunterladen; es schreibt nicht in einen Projektordner zurück, Bild-/Audio-/Video-Vorschauen von Ressourcen laden nicht über seine Speicher-API (Textressourcen lassen sich normal bearbeiten), und seine eingebaute Strukturprüfung ist leichter als der Node-Validator.
  • Die spieleigene SoundFont wird eingebettet, wenn vorhanden; die gemeinsame Ersatz-SoundFont ist eine Funktion des Node-Servers, sonst nutzt MIDI den eingebauten Synthesizer.
  • Die Umwandlung prüft kein Gameplay; die Node-Testsuites und der Browser-Testlauf bleiben die Referenzprüfungen.

Mit npm herunterladen

Das npm-Paket liefert die Node-Version: Launcher, Konverter und Studio-Befehle auf jeder Maschine mit Node.js 18 oder neuer. Global installieren:

npm install -g mwgp

mwgp serve                      # lokaler Launcher und Studio-Server
mwgp convert-auto RPGM_versions MWGP_versions
mwgp studio lift MWGP_versions/MeinSpiel/mwgp.json studio/MeinSpiel

Oder ohne Installation über npx:

npx mwgp convert-mv "pfad/zu/MeinSpiel" "MWGP_versions/MeinSpiel"
npx mwgp validate "MWGP_versions/MeinSpiel/mwgp.json"

Lieber aus den Quellen? Klonen Sie das GitHub-Repository, dann npm install und npm start. Die obigen Ein-Datei-Browser-Versionen werden aus diesen Quellen mit npm run export:converter und npm run export:studio erzeugt.

So funktioniert es

Die Konverter lesen die Daten des Originalprojekts (MV/MZ-JSON oder XP/VX/Ace-Daten und Ruby-Skripte, inklusive verschlüsselter RGSS-Archive) und schreiben ein ausdrückliches MWGP-Manifest: Karten mit ihren umgewandelten Ereignisbefehlen, die Datenbank, dekodierte Bilder und Audio, das eigene Plugin-JavaScript des Spiels und die transpilierte Ruby-Bibliothek. Der Player führt dieses Manifest im Browser aus; Ereignisskripte lassen den eigenen Code des Spiels in einer Sandbox laufen, sodass keine Spiellogik nachgebaut wird. Die Kompatibilität wird pro Projekt berichtet, und nicht unterstützte Formen erzeugen laute Warnungen statt stiller Auslassungen.
